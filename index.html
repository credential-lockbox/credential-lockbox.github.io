Credential Lockbox

Open-source tools for handing passwords and API keys to AI agents, so the secret never enters the chat. You encrypt it on your own device, and it's decrypted only for the tool that needs it. The agent itself never sees it.

See the projects GitHub

The idea

AI agents increasingly run tools that need real credentials. Pasting a password into chat puts it in transcripts, logs and the model's context. These projects keep it out of all three.

Your deviceLock itYou encrypt the credential to your agent's public key, in a browser page your agent sets up for you, or with a small script if you prefer the terminal.
→
Chat or a storeCarry itOnly ciphertext travels or is kept. Readable by no one without the agent's key.
→
The agent's machineUse itA helper decrypts it in memory and passes it straight to the one tool that needs it. The agent never sees it.

The lockbox in the icon is the whole idea: you put the credential in, and only the agent inside can open it. Its eyes are asterisks because it never sees the password either.

Shared principles

Every project here keeps the same promises, and says plainly where they stop.

What they keep

  • The secret never enters the chat or the model's context.
  • Nothing decrypted is written to disk by these designs.
  • The private key and the stored ciphertext never share a disk.
  • Install from pinned, reviewed releases, never a moving target.

What they can't do

  • Protect a compromised machine. You have to trust the computer your agent runs on.
  • Stop an agent that's been talked into misusing a credential. That's guarded by rules, not cryptography.
  • Save old copies if the agent's key leaks. Then you change the credentials at their services.

Each project's README carries its own full threat model.

Projects

Handoff

credential-lockbox

The core handoff: the agent-side helper that decrypts a credential in memory for one tool, setup and key-rotation instructions, and scripts for encrypting from a terminal on Linux, macOS or Windows.

Storage

s3-blob-store moving here

A dedicated store on Amazon S3, built for encrypted credentials and usable for any small, already-encrypted blob fetched by exact label. The agent fetches with a token and holds no AWS credentials. Deployed with one CloudShell paste.

Current home: cmeans/s3-blob-store

s3-blob-store-muse moving here

An operator console for s3-blob-store, built as a Muse Space: set the endpoint, then fetch, store and delete encrypted blobs by label.

Current home: cmeans/s3-blob-store-muse

Supported agents

Muse today. Other agents can be supported once they can run their own processes, where a secret can be decrypted and used without passing back through the conversation.

To start, ask your Muse to set up Credential Lockbox using the instructions in its README. The agent keeps the encrypted credentials in a store you choose, off its own disk; s3-blob-store is one option.
